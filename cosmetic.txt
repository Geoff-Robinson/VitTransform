! =====================================================================
! cosmetic.txt - LAYOUT ONLY. No code is rewritten.
!
! vitrules.txt changes what your code SAYS - StringTheory call patterns,
! redundant clips, dead guards. This file changes only how it LOOKS.
! Run it when you want a file tidied and nothing else touched:
!
!     VitTransform cosmetic.txt src\*.clw out --dry-run     see what would change
!     VitTransform cosmetic.txt src\*.clw out               write into out\
!     VitStyle cosmetic.txt                                 pick options visually
!
! WHY A SEPARATE FILE RATHER THAN A SWITCH. vitrules.txt has over 200
! ungrouped rules and ten ungrouped BUILTIN lines that are always on, and
! no --nogroup can silence them - a run prints the total beside 'ungrouped
! rules:'. A rule file is self-contained, so the honest way to get
! layout-only is a file that contains layout only. This one holds no
! rewrite rules at all, so there is nothing here that CAN change behaviour.
!
! WHAT RUNS WHATEVER YOU SELECT. Two tidy-ups live in the engine, not in
! any rule file, and they run whether or not anything else changed the file:
!   - trailing spaces and tabs are removed from the ends of lines
!   - a line wider than the file's own prevailing width is split at a
!     sensible point (after a ',' at the outermost call depth, before a
!     top-level '&', or after the opening '(')
! Either can be the ONLY change a run makes - that is what lets a
! layout-only run do useful work on a file the rules have nothing to say
! about. A file where even these change nothing is not written at all.
!
! LINE WIDTH. By default the limit is the file's own prevailing width plus
! 12, capped at 200 - so a codebase that keeps to 90 columns stays near 90,
! and one that already runs wide is not narrowed. Set it yourself with
!     --width=120
! or turn splitting off completely with
!     --width=0
!
! NOTHING BELOW IS ON BY DEFAULT except comment alignment. A plain
!     VitTransform cosmetic.txt src out
! aligns trailing comments and does nothing else. Add the groups you want.
! =====================================================================

NEEDBUILD 108                                        ! the minimum engine build this file needs

! ---------------------------------------------------------------------
! Line trailing comments up into a column.
!
! This is a whole-file layout change: in a file that is being changed
! anyway, it can move EVERY trailing comment, by up to 39 columns.
!
! On by default. To take the transformations without the re-layout:
!     --nogroup=cosmetic-aligncomments
!
! Clipping trailing spaces is a separate thing that always happens on a
! file that changed, and cannot be declined.
! ---------------------------------------------------------------------
GROUP cosmetic-aligncomments
BUILTIN AlignComments
ENDGROUP

! ---------------------------------------------------------------------
! Clarion keywords in lower case.
!
!     if x then loop until y ; end
!
! It covers the operators too - and, or, not, xor.
!
! This axis has three members: cosmetic-keywordcase-lower for lower case,
! -upper for UPPER CASE, and -title for Title Case. Only one can be on.
!
! No member is selected by default, so nothing is re-cased unless you ask:
!     --group=cosmetic-keywordcase-lower
! ---------------------------------------------------------------------
GROUP cosmetic-keywordcase-lower, CHOICE(keywordcase)
BUILTIN KeywordCase, STYLE('lower')
ENDGROUP
! ---------------------------------------------------------------------
! Clarion keywords in UPPER CASE.
!
!     IF x THEN LOOP UNTIL y ; END
!
! It covers the operators too - AND, OR, NOT, XOR.
!
! This axis has three members: cosmetic-keywordcase-lower for lower case,
! -upper for UPPER CASE, and -title for Title Case. Only one can be on.
!
! No member is selected by default, so nothing is re-cased unless you ask:
!     --group=cosmetic-keywordcase-upper
! ---------------------------------------------------------------------
GROUP cosmetic-keywordcase-upper, CHOICE(keywordcase)
BUILTIN KeywordCase, STYLE('upper')
ENDGROUP
! ---------------------------------------------------------------------
! Clarion keywords in Title Case.
!
!     If x Then Loop Until y ; End
!
! It covers the operators too - And, Or, Not, Xor.
!
! This axis has three members: cosmetic-keywordcase-lower for lower case,
! -upper for UPPER CASE, and -title for Title Case. Only one can be on.
!
! No member is selected by default, so nothing is re-cased unless you ask:
!     --group=cosmetic-keywordcase-title
! ---------------------------------------------------------------------
GROUP cosmetic-keywordcase-title, CHOICE(keywordcase)
BUILTIN KeywordCase, STYLE('title')
ENDGROUP

! ---------------------------------------------------------------------
! Re-indent the file, two spaces per nesting level.
!
! This axis has three members - cosmetic-reindent-2, -3 and -4 - one per
! width. Only one can be on.
!
! No width is selected by default, so indentation is left exactly as you
! wrote it unless you ask:
!     --group=cosmetic-reindent-2
! ---------------------------------------------------------------------
GROUP cosmetic-reindent-2, CHOICE(reindent)
BUILTIN Reindent, WIDTH(2)
ENDGROUP
! ---------------------------------------------------------------------
! Re-indent the file, three spaces per nesting level.
!
! This axis has three members - cosmetic-reindent-2, -3 and -4 - one per
! width. Only one can be on.
!
! No width is selected by default, so indentation is left exactly as you
! wrote it unless you ask:
!     --group=cosmetic-reindent-3
! ---------------------------------------------------------------------
GROUP cosmetic-reindent-3, CHOICE(reindent)
BUILTIN Reindent, WIDTH(3)
ENDGROUP
! ---------------------------------------------------------------------
! Re-indent the file, four spaces per nesting level.
!
! This axis has three members - cosmetic-reindent-2, -3 and -4 - one per
! width. Only one can be on.
!
! No width is selected by default, so indentation is left exactly as you
! wrote it unless you ask:
!     --group=cosmetic-reindent-4
! ---------------------------------------------------------------------
GROUP cosmetic-reindent-4, CHOICE(reindent)
BUILTIN Reindent, WIDTH(4)
ENDGROUP

! ---------------------------------------------------------------------
! One statement per line.
!
!     a = 1 ; b = 2 ; c = 3
!       ==>
!     a = 1
!     b = 2
!     c = 3
!
! A trailing ; with nothing after it is removed rather than left to
! produce an empty line.
!
! Off by default:  --group=cosmetic-splitstatements
! ---------------------------------------------------------------------
GROUP cosmetic-splitstatements, OFF
BUILTIN SplitStatements
ENDGROUP

! ---------------------------------------------------------------------
! Inline one-line conditionals opened out into block form.
!
!     if c then s.
!       ==>
!     if c
!       s
!     end
!
! Off by default:  --group=cosmetic-expandoneliners
! ---------------------------------------------------------------------
GROUP cosmetic-expandoneliners, OFF
BUILTIN ExpandOneLiners
ENDGROUP

! ---------------------------------------------------------------------
! Close a block with the END keyword.
!
!     if x
!       y = 1
!     end
!
! This axis has two members: cosmetic-blockend-end for the END keyword, and
! cosmetic-blockend-dot for Clarion's period shorthand, which writes the
! same block with a bare . in place of the end. Only one can be on.
!
! No member is selected by default, so block ends are left as you wrote
! them unless you ask:
!     --group=cosmetic-blockend-end
! ---------------------------------------------------------------------
GROUP cosmetic-blockend-end, CHOICE(blockend)
BUILTIN BlockEndStyle, STYLE('end')
ENDGROUP
! ---------------------------------------------------------------------
! Close a block with Clarion's period shorthand.
!
!     if x
!       y = 1
!     .
!
! This axis has two members: cosmetic-blockend-end for the END keyword, and
! cosmetic-blockend-dot for the period shorthand shown above. Only one can
! be on.
!
! No member is selected by default, so block ends are left as you wrote
! them unless you ask:
!     --group=cosmetic-blockend-dot
! ---------------------------------------------------------------------
GROUP cosmetic-blockend-dot, CHOICE(blockend)
BUILTIN BlockEndStyle, STYLE('dot')
ENDGROUP

! ---------------------------------------------------------------------
! A ready-made combination, for people who just want it tidy.
! It is the DEFAULT, so a plain
!     VitTransform cosmetic.txt src\*.clw out
! does the sensible thing with no switches at all.
!
! WHY THERE IS A DEFAULTSTYLE LINE: with no --style= on the command line
! every CHOICE axis resolved to (none), the only group left on was
! cosmetic-aligncomments, and `ungrouped rules: 0` meant there was nothing to
! fire - the run reported 0 changes and wrote nothing. A layout-only rule file
! that does nothing unless you know to pass --style= is a trap, not a default.
! ---------------------------------------------------------------------
STYLE tidy = cosmetic-aligncomments, cosmetic-keywordcase-upper, |
             cosmetic-reindent-2, cosmetic-splitstatements

DEFAULTSTYLE tidy
